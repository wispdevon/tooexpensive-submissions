# TooExpensive.dev project submissions

Have a useful alternative to share? [Submit a project for review](https://github.com/wispdevon/tooexpensive-submissions/issues/new?template=project.yml).

This repository is the public review queue for [TooExpensive.dev](https://tooexpensive.dev). A GitHub account is required. Everything in an issue is public: do not include private information, credentials, or customer data.

Include the job your project does, the tool it could replace, developer attribution, a working website or repository, use tags, and pricing/license details. Hosted services are welcome when clearly labeled; a public repository alone does not make a project open source.

## Review process

1. New submissions receive `needs-review`.
2. The website repository checks this public queue every 15 minutes once its automation is enabled. The admin page can also run a review immediately.
3. Personal repository owners can opt into automatic listing. The checks require an active public non-fork repository, a recognized open-source license, a short repository description, matching owner/profile attribution, known use tags, required submission fields, and no duplicate listing. Leave the website field blank for repository-only automatic listing. The entry uses canonical GitHub metadata and stores the owner's public avatar locally.
4. Passing entries are added to the directory and constellation in a content commit after automated tests and a Workers build check. Connected deployment publishes the updated site. Reports are visible to the maintainer in the admin page. These checks do not assess security, quality, feature parity, or total running costs.
5. Hosted services, organizations, recommendations, forks, custom tags, missing licenses, and submissions without automatic-listing consent require manual review. Maintainers can add them through the admin forms after checking details. Existing submissions remain eligible for manual review.

The automation does not post comments or close public issues. Maintainers can update issue labels and close issues after verifying publication. Public issue input is treated as data and is never executed.

Listing is not a guarantee of feature parity, cost savings, or endorsement. Keep comparisons specific and avoid unsupported claims about other products. Submitting your own project or a recommendation is welcome; disclose which it is.
